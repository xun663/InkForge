# P5-0.5 体系定向 Query A/B 实验报告

## 1. 实验目标
P5-0 的普通"断点续写"Query 偏向近期剧情，未能证明早期记忆的价值。本实验设计**明确依赖早期章节**的定向 Query（修炼体系/人物关系/长期伏笔/跨章节事实），验证 3/10/20/48 章 Coverage 下早期信息是否能被检索出来、进入 Context。

## 2. 与 P5-0 的关系
- P5-0：自动断点 Query（第 48 章近期事件）→ 最终 retrieved-memory 段不随覆盖增长（始终 3-5 条、命中 42-48 章）。
- P5-0.5：**手动定向 Query**（指向早期知识）→ 检验"存了但普通查询不调用"还是"没存够"。

## 3. 实验变量
唯一自变量 = Memory Coverage（3/10/20/48）。固定：BGE-M3 / deepseek-v4-flash / 1200 tokens / 8192 context / BM25+Vector→RRF(rrf-k=60)→PassThrough(top-8) / 同一 prompt。

## 10. LLM Answer Score（0-2）
**关键结论：LLM 作答受 deepseek 先验强烈干扰，不能作为检索成功的指标。**
- 反例：`3-D3`（韩飞羽冲突）EvCov=0（上下文无任何证据），但模型**答得正确详细**（韩长老炼还阳丹、返老还童诱因、主动寻衅）——纯靠模型对遮天的先验知识。
- `3-B2`（刘云志）EvCov=0 时模型答"上下文未提供"（遵守指令），`3-D3` 却输出先验知识——模型行为不一致。
- 因此 **LLM 答案分数无法可靠归因于记忆管线**；本报告以 **EvCov / Recall（检索指标）** 为准。

## 11. 每个 Query 的详细结果
存档于 `target/e2e/memory-coverage-directed/{3,10,20,48}-chapters/q-*.md`（每 query×coverage 含 trace/context/answer）。

## 12. Error 分类
- **B1（庞博关系）、C1（荒古圣体）、C2（九龙拉棺早期）**：**A = Retrieval Error**。证据在 48 章记忆中（人物/事件/摘要都有 sourceChapter），但定向 query 未能把它们选进 top-8 final——检索选择/排序问题，非记忆缺失。
- **B2、D2**：部分检索成功（早期章节被选中一部分）。
- **无 B（Memory Representation）明显证据**：记忆 dump 显示早期事实/关系/伏笔都正确抽取（如庞博第 10/18/25/39 章关系、荒古圣体第 37 章发现、九龙拉棺第 2/9/26 章事件），均在记忆中。

## 13. 3→10→20→48 边际收益
- **3→10**：A1 苦海、D1 百草液、D2 古经、D3 韩飞羽 大幅提升（早期事实开始可检索）。
- **10→20**：C3 荒古禁地、D2 古经 继续提升。
- **20→48**：B2 刘云志、C2 九龙拉棺 继续提升；D1/D3/C3 已达饱和。
- **B1（庞博关系）、C1（荒古圣体）**：即使 48 章也**不提升**（始终 0.20/0.67）——关系/伏笔证据未被检索选中。

## 14. 与 P5-0 结果对比
| | P5-0 断点 Query | P5-0.5 定向 Query |
|---|---|---|
| 早期记忆是否被检索 | ❌ 几乎不（top-8 只命中 42-48） | ✅ 部分（D1/D3/C3/B2/A1 命中早期章节） |
| Coverage 增加效果 | 3→10 后趋平 | **持续到 20-48 仍有提升**（D1/D3 到 48 饱和） |
| 关系/伏笔类 | 未测 | ❌ B1/C1/C2 即使 48 章也不被检索 |

**核心**：普通断点 Query 因"近期偏向"不调用早期记忆；**定向 Query 确实能调用早期记忆**（说明 Full Memory 有价值），但**检索选择对关系/伏笔类仍不足**。

## 15. 结论
**当前 InkForge 的长期记忆问题 = 两者都有：**
1. **"没存够"**（coverage 3/10 时）：D3/C3/B2 等早期证据根本不在记忆，定向 Query 无法检索（R@5=0）。
2. **"存了但不会找"**（coverage 48 时）：早期事实已入库，但**检索选择偏弱**——关系类（B1 庞博）、伏笔类（C1 荒古圣体、C2 九龙拉棺）的证据在 48 章记忆中却未被 top-8 选中（A 类 Retrieval Error）。

**最终回答：**
1. Full Memory 确实包含普通断点 Query 不触发的信息 → **是**（48 章记忆有完整早期事实）。
2. 早期信息能被定向 Query 检索出来 → **部分**（D1/D3/C3/B2/A1 能；B1/C1/C2 不能）。
3. 3→10 显著收益 → **是**（6/10 query 明显提升）。
4. 10→20 继续收益 → **部分**（C3/D2）。
5. 20→48 继续收益 → **部分**（B2/C2 提升，其余饱和）。
6. 瓶颈 = **Memory Coverage（3/10 不够） + Retrieval Selection（48 章仍漏关系/伏笔）**，非 Memory Representation。
7. **P5 下一阶段优先**：**Full Memory（把 3→全量，解决"没存够"）+ Retrieval Selection 优化**（query 语义化/关系抽取/更高 top-K/更好 reranking），而非 Memory Compression 先行——因为早期事实的检索问题（B1/C1/C2）主要出在"选不出来"，压缩无法解决"选不出来"，但 Full Memory 能解决"没存够"。

## 16. 下一步 P5 方向建议
- **P5 主线 = Full Memory 底座 + Query-aware Retrieval**：
  1. 实现全量 Memory Build（解决 coverage 3/10 的"没存够"）；
  2. 改进检索选择（体系定向 query 已证明早期记忆可被检索；需让普通断点查询也能调用早期关系/伏笔证据——query 扩展、关系检索、更高的 fusion top-K、可选 LLM Reranker）；
  3. Memory Compression / Narrative State 可作为后续（当记忆量大到需要紧凑状态时），但当前先解决"存够 + 找对"。

> 局限：单次生成、模型先验干扰 LLM 答案（3-D3 反例）、检索指标为 chunk/chapter 去重口径。若用"体系定向 query"作为生产查询入口（而非仅断点续写），Full Memory 的价值会显著兑现。
